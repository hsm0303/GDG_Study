이번 시간에는 api를 인터넷에서 사용할 수 있게끔 배포하는 법에 대해서 배웠다.
Dockerfile은 이미지를 생성하기 위한 설정 파일, 이미지는 Dockerfile을 바탕으로 앱과 실행환경을 담고 있으며 컨테이너는 실제 앱이 돌아가는 환경 역할을 한다.
각각 Dockerfile에서 작성이 되고 이미지를 통해 빌드가 되며 컨테이너를 통해 실행이 된다고 생각하면 될 것 같다.
AWS는 IT 자원을 제공하는 클라우드 서비스이며 EC2는 AWS에서 사용할 수 있는 가상 서버이다.
이미지는 Docker hub에 저장되어 있으며 EC2라는 서버에 전달이 되어서 실행된다.
클라이언트가 API를 요청을 한다면 EC2의 외부 주소를 통해 포트로 들어와 보안 그룸의 허용 규칙을 통과한 뒤, 포드 연결을 통해 컨테이너의 Spring Boot 앱으로 도달하는 과정을 거치게 된다.
외부에서 EC2에 배포한 API를 호출할 때, IP주소는 EC2서버의 위치를 찾아가는 역할을 하며 포트는 EC2 서버 내부에서 실행 중인 애플리케이션을 가리키는 역할을 한다.
실제 서버를 운영할 때에는 서버뿐만 아니라 데이터베이스와 IP주소 대신 사용할 도메인, 보안을 위한 암호화 등이 더 필요하다.
사용자가 많아져 서버 한 대로 감당하기 어려울 때는 트래픽 증가량에 맞춰 서버 개수를 자동으로 늘리거나 줄이는 오토 스케일링을 사용하는 방법이 있다.
EC2 외에 AWS Elastic Beanstalk라는 PaaS 서비스를 이용하여 배포하는 방법도 있다.
